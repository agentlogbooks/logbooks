# Stress test — the capture-first redesign (applied)

## Verdict

The applied redesign **closes the headline FEED gap but does not yet land capture-first cleanly, and it ships with a real toolkit regression** — so the honest answer to "capture-first, cleanly, without regressing the toolkit" is: *gap closed, not clean, fixable*. On the win side: the pre-redesign baseline that rated FEED **"no"** (`VALIDATION-import-iterate-visualize.md` — invocation form absent, supplied ideas fell through to `starter`, no real `generate.import` operator, FK wall on `frame_id_at_birth`, import never reached the wall) is now closed on the pasted-list happy path — invocation shapes exist (SKILL.md:24-25), Step 3a routes supplied ideas to a real `generate.import` operator first (SKILL.md:142-144), the Light-frame precondition resolves the FK (SKILL.md:372-384), and the `generate.*` emit row auto-populates the wall (SKILL.md:711). But the redesign introduces a **reproducible runtime break that hits every session, not just capture sessions**: both new operators declare `min_cohort: 0`, which the linter rejects (`operator_meta.py:198` requires `>= 1`), so `list-operators --format json` hard-exits with an error and emits no catalog at all — breaking Step 5D fragment validation (SKILL.md:499) and the Step 6 follow-ups read (SKILL.md:575). That is precisely the "regressing the existing toolkit" failure the task warns against, and the `smoke-capture-first.log` did not catch it because that run exercises only the orchestrator-direct brainstorm plumbing and never calls `list-operators`. Layered on top is a half-finished `starter` demotion: SKILL.md's catalog correctly calls `starter` "the *old* default" (SKILL.md:611), but the playbook source files the planner actually reads (`starter.md:3`, `starter.md:7`, `deep_explore.md:12`) still assert "default for fresh topics," and those files are live planner guidance — they can re-route a no-signal fresh intent back into the old frame+personas+compare machinery, defeating the core capture-first move.

## Dimension-by-dimension

### FEED gap closed — PASS
The prior-validated gap is closed on the path it was validated against ("here are my N ideas" on a fresh topic). Concrete evidence: two ingest invocation shapes added (SKILL.md:24-25) where the baseline had none; Step 3a routes supplied ideas to `generate.import` *first* in the fresh-topic ordering, ahead of opt-in starter and lean default (SKILL.md:142-144); `operators/generate.import.md` is a real, faithfulness-first transcriber writing via the real `add-ideas-batch` verb; the FK is resolved end-to-end via the Light-frame precondition + active-frame fallthrough (SKILL.md:372-384; `ideation_db.py` `_insert_idea` 616-625, `cmd_add_frame` 438-444, `cmd_add_ideas_batch` 685); and ingest auto-emits `idea_generated` via the `generate.*` emit row, with a live `view.html` handler (line 358). **Gap:** only the *pasted-list* form is wired; the advertised `--import <file>` form (SKILL.md:25, listed as trigger at 142) is unwired — no step reads the file into `source=`, and `generate.import.md` treats `source` as literal text, so a bare path is split as a path. The baseline-failed case is the pasted form, so this doesn't sink the dimension, but it is an advertised-but-dropped capability.

### Lean-default fidelity — PARTIAL
The default path is correct and matches the validated A/B arm: Step 3c plans exactly one `generate.brainstorm count=12` call with no checkpoint, no persona fan-out, no compare (SKILL.md:153, 200-214, 170); `generate.brainstorm.md` is a genuinely distinct, self-deduping, mechanism-first, persona-free generator ("ship THIS, not a repurposed generate.fresh", :33-35), and the smoke log confirms light frame → FK → 4 ideas → 4 `idea_generated` events end-to-end. The A/B data (`plain-vs-starter-result.json`: substance 4.09 vs 3.88, relevance 4.5 vs 3.88, distinct 13 vs 11.5, 4/4 judges prefer plain) supports shipping plain as default, and SKILL.md:211 cites it accurately. **Gap:** `generate.import.md:12` (`avoid_when`) still says "use generate.fresh (plain) or generate.seed (persona)" — but the plain generator is now `generate.brainstorm`; `generate.fresh` requires a `hint` and is not the plain default. This is exactly the dangling-reference class the task flags, sitting in the ingest sibling's metadata that the planner reads. (Minor: `generate.import.md:54` calls the frame step "a light frame.discover" when the shipped path only inserts the `frame.light` placeholder.)

### Techniques preserved — FAIL
The toolkit is *present and routable*: nothing removed (operators/ = 28 = 26 prior + 2 new; all 10 playbooks; personas 6, zones 6), `--techniques`/"structured"/"personas"/"frame it properly" route to `starter` (SKILL.md:147, 228-244), opt-in triggers for deep_explore/quick_seed/naming/reframe are intact (SKILL.md:148-151), and frame-on-first-iterate correctly defers the real `frame.discover` + checkpoint with a matching sentinel (SKILL.md:157/378). **What fails it:** the `starter`-is-the-default demotion was applied to the SKILL.md index but **not to the playbook source files the planner reads** — `starter.md:3` ("Lightweight default."), `starter.md:7` ("Default for fresh topics… pick this"), and `deep_explore.md:12` ("Default case… Use starter") all still assert the old default. The planner is told to read "when-to-pick notes" and "load that playbook verbatim" (SKILL.md:130/134), and the prep step only `ls`es the dirs (SKILL.md:116), so these files *are* the planner's sole source of when-to-pick guidance — handing it two contradictory rules for the same "brainstorm / no-signal" phrasing and risking a re-route back to the old machinery. This is the exact dangling "starter is the default" reference the task names as a FAIL. Compounding it: the REDESIGN spec'd the `--techniques` entry in the Step 6 "Try next" menu as the mitigation against "techniques deferred → never used," but SKILL.md:562-567 omits it — a spec'd-but-unimplemented discoverability requirement.

### Internal consistency — FAIL
**Reproducible hard break:** both new operators declare `applies_to.min_cohort: 0` (`generate.brainstorm.md:6`, `generate.import.md:6`); `operator_meta.py:198` requires int `>= 1`; `load_catalog` raises on the first failure (`operator_meta.py:257`) and `cmd_list_operators` turns it into `sys.exit("ERROR: …")` (`ideation_db.py:1430-1440`). Running `list-operators --format json` prints `ERROR: generate.brainstorm.md: - applies_to.min_cohort must be an integer >= 1` and emits no JSON. This breaks Step 5D (SKILL.md:499) and Step 6 follow-ups (SKILL.md:575) — and Step 6 is reached by the redesign's *own* flagship capture path (Step 3c closes by offering the Step 6 menu), so capture sessions are hit too. The existing pool-scope generators (`generate.fresh`/`generate.seed`) correctly declare `min_cohort: 1`, so this is a new divergence. Also in-dimension: the stale `generate.import.md:12` `avoid_when` pointer (above) and the unwired `--import <file>` advertisement. **Passes:** no leftover "starter is the default" in SKILL.md itself; catalog counts match disk for frame/generate/transform/evaluate/validate; `frame.light` is consistently orchestrator-internal and never a subagent; the `generate.*` emit/phase wildcards cover both new operators; the checkpoint-insertion exemption is coherent with the frameless default. (Pre-existing, *not* this redesign: SKILL.md:604 decide.* "(4)" omits `decide.route` though 5 files exist — `git show HEAD` confirms it predates the change.)

## Caveats

This is a spec/static review of the actual edited files plus a single CLI smoke run (`smoke-capture-first.log`) and one empirical reproduction of the `list-operators` linter failure. The smoke log validated the `generate.brainstorm` plumbing end-to-end (light frame → FK resolved → ideas → wall events) but **never calls `list-operators`**, which is exactly why the `min_cohort: 0` break passed the smoke test undetected. The FK-resolution and auto-emit behavior for `generate.import` is proven *by construction* (identical `add-ideas-batch` → `None` → active-frame fallthrough, same Light-frame precondition, same `generate.*` emit row) and inherited from the observed brainstorm run, not from an import-specific smoke run — mirroring the prior validation's construction-vs-observed caveat. The full orchestrator → planner → subagent interactive path was validated by construction and plumbing, not by a complete interactive end-to-end session.
